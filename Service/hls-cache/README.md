# HLS/CMAF 正式资产目录

此目录映射到 Service 容器内的 `/app/hls-cache`，保存转码完成的视频清单、初始化片、媒体分片、封面和 `asset.json` 元数据。

新增产物按 `{原分类文件夹}/{视频ID}/{版本}/` 保存，中文名称和嵌套目录原样保留；没有父分类的视频存入 `未分类/{视频ID}/{版本}/`。分类层可以直接看懂并整体备份、下架；视频 ID 和版本层仍用于稳定播放地址和避免重名。

新版服务仍能读取旧的 `{视频ID}/{版本}/`。旧资产只通过显式迁移整理：先停止服务、备份整库，再运行新版程序 `--migrate-hls-folders /app/hls-cache` 预览，核对后增加 `--apply --service-stopped` 执行。工具逐文件校验、不重新转码、不覆盖目标；完整部署及回滚顺序见项目根目录 `README.md` 的“整理旧版转码目录”。

`Service/media` 是新增内容收件箱。服务只处理新放入的 MP4；正式资产完整发布后，才会清理对应的源 MP4 和同名人工封面。不要在转码期间手动移动临时目录。

目录内容由 Git 忽略，但应纳入服务器文件备份。删除这里的正式资产会让对应视频从列表消失，且源文件已清理后无法自动重建。

下架分类建议停服后将选中的分类目录移至本资产库之外的备份目录，再启动新版服务并刷新列表。不要只在库内改名，不要改动内部 ID、版本、`asset.json`，不要在服务运行时移动目录。
